How AI coding agent sandboxes actually work

  • A sandbox is a container with its own filesystem, resource limits, and network restrictions that stops malicious code from accessing your API keys or machine.
  • Agents can leak API keys just by making an outbound network call (e.g., posting them to an external server) even without breaking out of the container, so network allowlists (only permitting approved destinations like GitHub, npm, your model API) are used in production instead of full network blocks.
  • Credential proxies (used by Daytona) store only fake placeholder keys inside the sandbox; an external proxy swaps in the real key only for approved API requests, so the code never sees the actual key.
  • One Docker command can set memory/CPU caps, a read-only filesystem, and network isolation for a basic sandbox; higher-risk workloads use microVMs like Firecracker, which give each agent its own isolated kernel instead of sharing the host's.
  • Snapshots save an agent's full environment state (cloned repos, installed packages, files already read) so repeated setup work isn't redone on every interaction, making the sandbox feel like a persistent personal computer.
