Post-Quantum Cryptography for Ethereum Wallets

  • Researchers propose combining EIP-8141 (programmable account validation, letting each wallet pick its own signing method) with EIP-8288 (recursive STARK aggregation, a proof technique compressing multiple signatures) so the network verifies one proof instead of each signature separately
  • Efficiency varies widely across five post-quantum candidates on Apple M4 Pro hardware: FORS fits 100 signatures into 298 KiB, Falcon-512 fits 32, ML-DSA-44 fits 6, and standard Raccoon-128 fits only 1 signature per proof
  • Raccoon-G exceeds the 268M-word witness cap (memory footprint allowed per signature proof), requiring Merkle-tree-style recursive aggregation across five sub-proofs per signature, producing a 333 KiB root proof plus 2.84 KiB auxiliary data for 100 signatures

Multidimensional Fee Markets vs. Single-Resource Metering on Ethereum

  • EIP-7999 delivers 4%-34% more execution gas per block than the best one-dimensional fee alternatives while holding state growth (total size of blockchain state data) to 120 GiB/year, versus 56.7-96.0 GiB/year for single-resource approaches
  • Against an EIP-4844-style one-dimensional fee market based on blob transactions at a 4/5 target-to-limit ratio, EIP-7999's max-throughput setup adds 19.5M-56.2M gas per block while keeping near-limit block rates below the 38.8%-40.8% produced by that approach
  • Supports Ethereum's shift from separate metering (tracking resources individually) to separate pricing (charging differently per resource) to enable higher throughput as the network scales

Prompt injection attacks remain a key AI agent safety risk

  • When AI agents browse webpages or documents, those sources can contain hidden instructions (prompt injection attacks) designed to override the user's original task.
  • Recommended safeguards: specify one clear task, treat all webpage/file content as untrusted (never as instructions), and require approval before any message is sent, file shared, or purchase made.
  • OpenAI's prompt-injection evaluation measures resistance but not immunity; keeping sensitive files out of unnecessary browsing workflows remains the safest approach.
